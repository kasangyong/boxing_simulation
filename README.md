# Boxing RL

3D 휴머노이드 복싱 시뮬레이션. 두 AI 에이전트가 강화학습 + 자기대전(Self-Play)으로 복싱을 학습합니다.

> **현재 상태 (2026-03-20)**: Self-Play 학습 중 — 119,000,000 / 300,000,000 스텝 (40%)

## 학습 방식

### Self-Play 구조

```
train.py --selfplay --n-envs 4
    │
    ├── SubprocVecEnv (병렬 환경 4개)
    │       각 환경: SelfPlayEnv
    │           ├── fighter_0  ← PPO가 학습하는 에이전트
    │           └── fighter_1  ← 50K 스텝마다 업데이트되는 frozen 상대
    │
    └── PPO (MlpPolicy: [256, 256, 128])
```

- `fighter_0`이 학습하며, `fighter_1`은 50K 스텝마다 현재 정책으로 업데이트됩니다.
- 상대가 강해질수록 학습 난이도가 자연스럽게 높아집니다.

### 보상 구조 (현재)

| 항목 | 값 | 비고 |
|------|----|------|
| 생존 보상 | +0.1 / 스텝 | 서있는 동안 |
| 직립 보상 | +0.2 × (torso_z / 0.9) | 최대 0.2 |
| 근접 보상 | +0.8 × max(0, 1 - dist / 2m) | 거리 2m 이내 |
| 접근 보상 | +0.5 × 좁혀진 거리(m) | 매 스텝 거리 감소량 |
| 주먹 속도 | +5.0 × 상대 방향 이동량 | 1.5m 이내, 타격 전 동작 장려 |
| 주먹 명중 | +5 × force × 0.01 | 접촉 시 |
| HP 데미지 (가함) | +데미지 × 10 | |
| HP 데미지 (받음) | -데미지 × 7 | |
| KO 승리 | +100 | 엣지 트리거 (1회) |
| KO 패배 | -100 | 엣지 트리거 (1회) |
| 에너지 페널티 | -0.005 × Σaction² | |

### KO 조건

- 토르소 z < 0.45 (쓰러짐)
- HP ≤ 0 (체력 소진)

## PPO 하이퍼파라미터

```python
learning_rate = 3e-4
n_steps       = 2048       # 환경당 롤아웃 길이
batch_size    = 64
n_epochs      = 10
gamma         = 0.99
gae_lambda    = 0.95
clip_range    = 0.2
ent_coef      = 0.0001     # std 억제를 위해 축소 (기본값 0.001)
target_kl     = 0.05       # KL 초과 시 업데이트 조기 종료
net_arch      = [256, 256, 128]
n_envs        = 4          # SubprocVecEnv 병렬 환경
```

## 물리 설정 (boxer.xml)

| 항목 | 값 | 비고 |
|------|-----|------|
| Joint stiffness | 0 | 수동 직립 지지 제거 — 능동 균형 강제 |
| 다리 actuator kp | 150 | 이전 350에서 축소 |
| 발목 actuator kp | 100 | |
| 총 액추에이터 수 | 42 | 에이전트당 21개 |

> stiffness=0 설정의 핵심: 이전 설정(stiffness=5, kp=350)에서는 ctrl=0(정책 없음)이 186 스텝 생존 가능했고, 훈련된 정책은 160 스텝밖에 못 버팀. 물리가 정책 없이도 서있을 수 있도록 지지해줬기 때문. stiffness=0으로 바꾸면서 에이전트가 능동적으로 균형을 배워야 함.

## 주요 트러블슈팅 이력

| 문제 | 원인 | 해결책 |
|------|------|--------|
| 에이전트가 쭈그리고 앉음 | upright 보상 선형 → 쭈그리기가 이득 | 계단형 upright 보상 |
| 컨트롤이 0에 고정 | energy 페널티 과다 | -0.005 → -0.001 |
| std 폭발 (3.8→4.4) | ent_coef=0.01 과다 | ent_coef=0.001 + target_kl=0.05 |
| 훈련 정책이 ctrl=0보다 나쁨 | stiffness=5, kp=350 수동 직립 지지 | stiffness=0, kp=150 |
| 커리큘럼 10K 스텝 만에 전 Phase 통과 | 새 물리에서 초기 R=170+, 임계값 즉시 초과 | 커리큘럼 스킵, 바로 Self-Play |
| std 재폭발 (1.0→1.93) | ent_coef=0.001 여전히 과다 | ent_coef=0.0001 |
| 에이전트들이 서로 멀어짐 | 근접 보상 부족 | proximity 0.3→0.8, approach +0.5/m 추가 |
| KO 보상 중복 발화 | opp_ko 레벨 트리거 (쓰러진 동안 매 스텝) | 엣지 트리거로 수정 |
| watch.py 창 안 뜸 | 백그라운드 프로세스 GUI 제한 | 사용자 본인 터미널에서 직접 실행 |
| watch.py가 오래된 체크포인트 로드 | mtime 기준 정렬 (재시작 시 14M이 66M보다 최신) | 스텝 수 기준 정렬로 수정 |

## 프로젝트 히스토리 — Phase & 보상 변화 기록

### Phase 1~3: 커리큘럼 학습 (초기 설계)

초기에는 4단계 커리큘럼으로 설계:

| Phase | 목표 | 보상 |
|-------|------|------|
| 1 | 직립 균형 | upright 보상만 |
| 2 | 이동 | upright + 이동 |
| 3 | 상대 인식 | 위 + KO/HP |
| 4 | Self-Play | 전체 복싱 보상 |

**문제 발생**: 물리 설정 변경(stiffness=0, kp=150) 이후 초기 보상이 R=170+으로 치솟아
커리큘럼 임계값(80/120/180)을 10K 스텝 만에 모두 통과 → 커리큘럼 의미 없어짐.
→ **커리큘럼 건너뛰고 바로 Self-Play로 전환**.

### Self-Play 학습 — 보상 변화 추이

| 시점 | 스텝 | 평균 R | 변경사항 |
|------|------|--------|---------|
| 시작 | 0 | ~45 | Self-Play 첫 시작 |
| 초기 | 500K | ~68 | — |
| 초기 | 1M | ~70 | — |
| 정체 | 2M~4M | ~75 | — |
| 물리 수정 후 | ~10M | ~96~105 | stiffness=0, kp=150 + proximity(0.8) + approach(0.5) 추가 |
| 현재 | ~119M | 측정 중 | fist velocity 보상 + KO 엣지 트리거 수정 |

---

### 보상 함수 변화 이력

#### 초기 (Self-Play 시작 시)
```
생존 보상       +0.1/스텝
직립 보상       +0.2 × (z / 0.9)
주먹 명중       +5 × force × 0.01
HP 데미지(가함) +데미지 × 10
HP 데미지(받음) -데미지 × 7
KO 승리/패배    ±100  (레벨 트리거 — 버그)
에너지 페널티   -0.005 × Σaction²
proximity       +0.3 × max(0, 1 - dist/2m)
```

#### 1차 수정 (~10M 스텝, 2026-03-19)
- **문제**: 에이전트들이 서로 멀어지며 서있기만 함
- proximity 보상 `0.3 → 0.8` 상향
- approach 보상 `+0.5/m` 신규 추가 (매 스텝 거리를 좁힐수록 보상)
- **결과**: R이 75 → 96~105로 상승, 에이전트들이 서로 접근하기 시작

#### 2차 수정 (~119M 스텝, 2026-03-20)
- **문제 1**: KO 보상이 상대가 쓰러진 동안 매 스텝 중복 발화
  - `opp_ko` 엣지 트리거로 수정 (처음 쓰러지는 순간 1회만 지급)
- **추가**: fist velocity 보상 — 주먹이 상대 방향으로 움직일 때 보상 (타격 전 동작 장려)
  - 거리 1.5m 이내일 때만 활성화 / W_FIST_VEL = 5.0
